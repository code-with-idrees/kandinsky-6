# Kandinsky 6 on an RTX 3090 (24 GB, Ampere)

The RTX 3090 is Ampere `sm_86`: 24 GB of VRAM, no FP8 tensor cores, and no
FlashAttention 3. It runs Kandinsky 6, but which checkpoint it runs depends as
much on **system RAM** as on VRAM. This page is the 24 GB recipe.

## Which checkpoint fits

`offload: block` and `offload: module` keep the whole checkpoint on the host and
stream what the current stage needs. That makes Pro fit in 24 GB of VRAM and it
is why the 24 GB RTX 4090 preset works on a 128 GB workstation. The host side is
the catch:

| Checkpoint | DiT | Qwen2.5-VL text encoder | VAEs + vocoder + CLIP | Total | Host RAM with offload |
|---|---:|---:|---:|---:|---:|
| `lite-distill` | 5.9 GiB | 15.5 GiB | 3.4 GiB | 24.8 GiB | ~25 GiB |
| `pro-distill` | 56.2 GiB | 15.5 GiB | 3.4 GiB | 75.1 GiB | ~75 GiB |

So a 32 GB workstation can run `lite-distill` and cannot stage `pro-distill`
at all, on any GPU. `kandy doctor` computes exactly this and refuses the load
before an 80 GB download starts.

The shipped preset `kandinsky/configs/devices/rtx-3090.yaml` therefore uses:

* `checkpoint: lite-distill` — 3B DiT, 10 PiFlow steps, 480x864, 121 frames, audio on
* `offload: none` — nothing is streamed; nothing waits on PCIe
* `text_embedder.quantized_qwen: true` — NF4 keeps Qwen at ~4.3 GiB
* `attention: auto` — SageAttention when installed, SDPA otherwise

Resident VRAM is roughly 5.9 (DiT) + 4.3 (NF4 Qwen) + 3.4 (VAEs) + ~2
(activations) ≈ 15.5 GiB, which leaves room for the desktop compositor on a
24 GB card. The VAE decoder sizes its own tiles from free VRAM, so the decode
pass does not need a separate low-VRAM mode.

With `offload: module` and a bf16 text encoder instead (higher prompt fidelity,
~25 GiB host RAM, ~15.5 GiB peak VRAM) the same card also works; it is slower
because every stage change copies weights over PCIe.

## Windows 11

Everything above applies; the differences are in the toolchain.

```powershell
git clone https://github.com/kandinskylab/kandinsky-6.git
cd kandinsky-6
powershell -ExecutionPolicy Bypass -File scripts/setup-gpu.ps1
.\.venv\Scripts\python.exe -m kandinsky doctor
.\.venv\Scripts\python.exe -m kandinsky generate "a cat on a mat"
```

`setup-gpu.ps1` reads `compute_cap` from `nvidia-smi`, runs `uv sync --extra
consumer`, and prints the doctor report. Notes:

* **SageAttention is optional.** Its CUDA extension needs `nvcc` plus MSVC and
  builds with `-Sage` only. Without it, `attention: auto` resolves to PyTorch
  SDPA, which uses the fused FlashAttention kernel in the CUDA wheel. On `sm_86`
  that is the sensible default; SageAttention 2.2.0's Ampere kernel is a
  per-thread INT8 path that mostly wins on very long sequences.
* **Hugging Face cache symlinks.** Without Developer Mode, `huggingface_hub`
  copies instead of linking, so the cache needs ~2x the checkpoint size on disk.
  `kandy download lite-distill` still verifies the snapshot correctly; it is only
  disk usage.
* **Long first run.** Weight load plus the first text encode is CPU-bound. Expect
  a few minutes before the denoise bar moves, and let Windows keep the pagefile
  on the system drive if you use `offload: module`.
* **PyAV encoding.** `av` writes H.264 (libx264) into the MP4, so no separate
  FFmpeg install is needed.
